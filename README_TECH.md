# FundAI 技术文档 · 架构 · 算法口径 · 十年实证与审计

> 本文件是 **FundAI · AI-Powered A-Share Fund Decision System** 的技术主文档：
> 架构总览、每日决策流、算法口径（选基 / 仓位 / 风控）、十年实证与四窗口独立回测、
> 全程序审计与修复清单、已知边界与诚实结论。
> 项目定位与快速上手见发布版首页 `README.md`（同目录下的门面文档）；
> 便携包说明见 [`README_PORTABLE.md`](README_PORTABLE.md)。

**它的证据**：仓库自带**十年（2017-09 → 2026-09）实证报告**与四窗口（牛/熊/震荡/全历史）
独立回测：固定基准仓位 + 十年消息面 + 反应型风控在 2017-09→2026-09 的**九个年度**上做到
**+85.8% / 最大回撤 19.9%**（同期沪深300 +18.6%）。所有结论都可用 `data/` 下的脚本逐条复现。

> **默认配置**：起始资金 **1000 元**、默认目标倍数 **×1.3**、默认观察期半年 ——
> 这只是**开箱默认值**，用来演示"目标进度 / 达标判定"这类功能；
> 起始资金、倍数、期限都可以在网页参数面板或 `python app.py init --cash N` 里任意自定义。
> 系统的价值在**决策辅助与可复盘性**，不在任何收益倍数。

**一句话架构**：多源新闻 + 十年电报库 + 涨停情绪 + 行情技术面 → 三路评分 + 事件语义 + LLM 研判
→ 评分驱动的**选基**与**固定基准仓位** → 反应型风控（止损/均线/冷却）→ 每日建议（人工执行记账）
→ 自动结算与自检命中率 → 网页可视化。

**先看这一条（诚实提示）**：日频方向预测的样本外上限通常在 55–60%，
本项目十年实测为 **52–56%**；**没有任何模型能稳定“预测”明天**。
所以本系统的定位是**决策辅助与纪律工具**，而不是“预测机器”。十年回测的结论是：
用**固定基准仓位（70%）+ 十年消息面 + 反应型风控（基金级止损 + 均线减仓 0.10 + 回撤冷却 0.10）**
在 2017-09→2026-09 的**九个年度、四个独立市场状态窗口**上做到 **+85.8% / 最大回撤 19.9%**
（同期沪深300 +18.6%），但**参数曲线并不平滑、单点最优不可信**（见 §6.5 与 §12）。
请把它当成研究/教学工具，不构成投资建议。

## 二、快速开始

**方式一：从发行包起步（推荐给新环境）** —— `dist/fundai-portable-<版本>.zip` 解压即用，
不含密钥/数据库/缓存，首次运行**自动生成 `config.json`**（内置通用起始基金池，
不加载任何人的 key 与本机地址）：

```bat
python app.py doctor          :: 环境自检
启动服务.bat                   :: 起网页（http://127.0.0.1:8787）并自动打开浏览器
python app.py run-daily       :: 收盘后跑一次研判
install_tasks.bat             :: （可选，管理员）按安装目录注册 6 个计划任务
```

**方式二：源码树（本仓库，含十年数据与研究脚本）**：

```bash

python -m pip install numpy

# 2) 初始化账户：起始资金任意，目标线自动 = 起始资金 × 1.3（+30%）
python app.py init --cash 1000                 # 默认：目标线自动 1300
python app.py init --cash 5000                 # 目标自动 6500
python app.py init --cash 1000 --target-multiple 1.5   # 想改倍数也行
python app.py init --cash 1000 --target 1400   # 或直接指定目标金额

# 3) 每日流程（收盘后 ~21:30）
python app.py news-pull                 # 拉取多源消息 + 打标入库
python app.py run-daily                 # 研判 + 下单建议 + 快照 + 自检结算
python app.py signals-update --days 7   # 事件→次日涨跌样本结算（校准用）

# 4) 网页（默认 127.0.0.1:8787）
python app.py serve

# 5) 回测 / 研究（**已并行**，默认铺满 CPU；--jobs N 可限流）
python app.py backtest --months 6
python app.py event-model --days 4000 --select
python data/regime_study.py --dd 25      # 6000 组组合扫描（约 4 秒）
python data/regime_backtest.py           # 124 个引擎回测任务（约 4 分钟）
python tools/bench_parallel.py           # 并行加速基准（可复现的数字）
```

**打包 / 自检（各一条命令）**：

```bash

python tools/verify_release.py   # 从产物本身解压→起服务→跑测试（12 项检查）
```

**Windows 计划任务（已配置）**：`fundai_keepalive`（每 15 分钟保活）、
`fundai_intraday`（工作日 12:00 午间诊断）、`fundai_run_daily`（21:30 研判 + 补拍快照）、
`fundai_run_daily_late`（22:45 兜底）、`fundai_daily_signals`（20:30 事件样本结算）、
`fundai_direction_check`（23:05 **AI 次日方向判断的自检**：补记方向 + 结算命中率，
独立于研判任务，研判当天已跑过也会照常补齐）。
新环境用 `install_tasks.bat`（管理员）按安装目录重新注册。

> **AI 次日方向判断（自动记录 · 自检命中率）怎么跑**（2026-09-12 修复）：
> 方向 = 合成评分（平滑后）经 `analysis.view_of` 推导，判断日收盘给出、写一行到
> `screening.db` 的 `direction` 表；下一交易日收盘后用当日涨跌结算命中
> （看多=涨、看空=跌、中性=|涨跌|≤0.3%），命中率在「消息与进化」页。
> 修复前这一步嵌在 `run_daily` 中段，遇到 `has_record(D)` 短路（当天已跑过一次、
> 晚间只补拍快照、或白天先手动跑）就整体跳过；周末/节假日又因面板判定条件过窄而
> 空白。现在：`run_daily` 主流程与短路路径都会跑 `Engine.direction_record()`，
> 也可单跑 `python app.py direction-check [--date D]` 补记/结算，写库失败不再静默。

## 三、架构总览

```
数据层        clsdb(SQLite 电报库) · datasource(行情/净值/多源K线) · microstructure(涨停情绪)
              screening(SQLite 消息库/打标/学习词/方向记录/午间记录) · calib(结算样本)
              api_usage(分源配额计数/降级状态，持久化到磁盘)
算法层        lexicon(词典/符号折算) · semantics(事件语义) · news(消息聚合/口径/按日历史聚合)
              analysis(量化分+LLM+动态权重) · indicators(技术指标) · strategy(选基/仓位/风控/轮动)
              microstructure(情绪分/题材热度) · event_model(事件→方向 样本外模型)
              risk_overlay(预测型风控，默认关闭) · intraday(午间诊断)
调度层        engine(run_daily/simulate/backtest/state_payload) · web(HTTP API + 静态页) · llm_news(LLM 逐条定级)
配置层        settings(默认值+校验+热重载) · param_docs(126 个参数的中文说明元数据) · configedit(校验后写入+备份+回滚)
呈现层        web/static/{index.html,app.js,style.css,vendor/echarts.min.js} · app.py(23 个 CLI 命令)
保障层        tests/(260 项) · data/namecheck.py(未定义名扫描) · 一致性校验(资金守恒)
研究层        data/harness.py(评估内核/窗口枚举) · regime_study.py · regime_backtest.py(阉割+最终组合)
```

### 每日决策流（`run_daily`）

```
index_history → D(最近收盘日) → 结算到期 T+1 订单 → 午间诊断结算
 → 量化分(analysis.score_market)  +  消息分(重点事件口径 / 人工打标优先)  +  情绪分(涨停微观)
 → 动态权重微调(消息±3% / 情绪±3%)  →  合成评分(量化50% 消息35% 情绪15% 基准)
 → 题材热度(3日衰减)  →  选基(动量+多因子, 同主题≤1)  →  仓位(固定70%基准 → 硬上限80%)
 → 反应型风控(跌破MA60/120减仓, 底仓40%; 单只-8%止损; 峰值回撤10%冷却5天)
 → 订单(买入/赎回/转换)  →  记录(calc 评分明细)  →  快照  →  资产曲线自愈回填
```

## 五、算法体系

### 5.1 三路评分（合成比例见下）

| 维度 | 来源 | 权重（基准） | 十年实测边际 |
|---|---|---|---|
| 量化技术面 | MA20/60/200、RSI、5/20 日动量、乖离、量价 | 50% | 主要信号来源（含短期反转） |
| 消息面 | 财联社/东财/新浪 → 事件语义 + 词典 + LLM 定级；人工打标优先 | 35% | 事件级 +3~+5pp，**日级 IC 仅 +0.02** |
| 情绪微观 | 涨停池/炸板率/晋级率/涨跌停结构（借鉴 Cailianpress-Feishu-Bot） | 15% → **现 10%** | IC −0.077（轻微反向） |

**动态权重**：消息净情绪 |net|≥4 → 消息 +3%；情绪分位两端 → 情绪 −3%；波动率 ≥90% 分位 → 两者各 −3%；
限幅 消息∈[0.25,0.40]、情绪∈[0.05,0.15]（`analysis.dynamic_weights`，每日在研判文案中列出）。

### 5.2 消息面口径治理（三轮迭代）

1. **事件语义层**优先（央行/政策/业绩/增减持/地缘/权益披露…），词典作兜底；
2. **例行噪音自动归档**：ETF 溢价、机构持股披露、同模板刷屏（骨架相似度 ≥0.82 自动归并）；
3. **词典层关闭**（`news_dict_mode="off"`）+ **重点事件口径**（`news_focus_events`）+ 反向刻度换算；
4. **LLM 逐条定级**（`news_llm_enable`，默认每天 ≤120 条，判中性/无关即**一票否决**，
   与词典标签一致率 94%，但**不提高日级命中率**——定位是降噪与人审提示，方向默认不加权）。

### 5.3 事件语义层实测（十年，2189 交易日）

| 事件×方向 | 样本 | 命中率 | 增量（相对基线） | p |
|---|---|---|---|---|
| 股东增减持·利多 | 27,988 | 56.0% | **+5.5%** | <0.001 |
| 业绩·利多 | 13,290 | 54.8% | **+4.3%** | <0.001 |
| 词典兜底·利多 | 198,845 | 54.0% | **+3.5%** | <0.001 |
| 产业政策·利多 | 8,810 | 53.5% | +3.0% | <0.001 |
| 央行宽松·利多 | 7,522 | 53.4% | +2.9% | <0.001 |
| 地缘冲突·利空 | 17,365 | 49.1% | −0.4% | 0.31 |
| 词典兜底·利空 | 73,745 | 45.4% | −4.0% | <0.001 |

> ⚠️ 5.4 年窗口曾得出"词典层两个方向都是负增量"的结论，十年样本推翻之（窗口偏差）。
> 但**日级口径对照**显示：词典全量 / 仅重要 / 关闭三者的 IC（+0.016~0.021）与命中率
> （49.1~49.7% vs 基线 50.5%）**差异都在噪声内** → 口径保持"重点事件 + 词典关"（更简单、可解释）。

### 5.4 题材热度（涨停概念 + 风口 → 选基主题）

单日强度 = 概念涨停家数 + **0.5×**最强风口家数（去重）→ 转**当日占比** → 按 [0.5/0.3/0.2]
时间衰减（新→旧）→ **持续性加成**（窗口内每多 1 天 ×1.12）→ 归一化；
今日占比 ≥ 其余日均值 1.5 倍且 ≥8% → 标 **🔥 点火（新热点）**。算法与传参顺序无关。

### 5.5 事件→方向模型（样本外，仅作参考信号）

walk-forward（预测第 t 日只用 <t 数据）+ 选择性出手（阈值只在训练窗内定）+ 特征子集对照
+ 选择期/留出期分离。特征：事件三组×多空、制度状态（均线/波动分位/回撤）、跨市场风格强弱、
制度交互项（趋势×位置、趋势×连涨跌、波动×连涨跌…）。

**十年结果（2190 交易日 / 样本外 2130）**：方向命中 **52.3% vs 基线 50.3%（+2.0pp）**，
选择性出手 51.4–54.3%，留出期 +1.4pp；**策略跑输买入持有（0.9659 vs 1.1138）**。

### 5.6 风控：从"预测型"转为"反应型"

| 规则 | 参数 | 说明 |
|---|---|---|
| 单只浮亏 **−8%** → 止损清仓 | `risk.fund_stop_loss_pct` | 反应型，规则明确 |
| 单只浮盈 +10% 锁一半 / +25% 全落袋 | `fund_take_profit_pct/_full_pct` | 止盈纪律 |
| **跌破 MA60/MA120 → 每档减 20%**（底仓 40%，MA20 破位噪声大默认跳过） | `ma_break_step/_max/_floor/_skip_ma20` | 新增，站回均线自动恢复 |
| 峰值回撤 **10% → 冷却 5 个交易日**（降仓至 25%） | `peak_trailing_pct`、`rearm_days=5` | 组合级 |
| 组合止损 −15% | `portfolio_stop_pct` | 组合级 |
| 硬上限 **80%**（永不满仓） | `equity_hard_cap` | 全局 |
| 预测型过滤（模型 P(涨)） | `risk_overlay_enable=false` | **默认关闭**（十年负贡献） |

### 5.7 仓位结构（三层，最终定稿）

```
最终权益目标 = clamp( 固定基准 70% + 调整带(默认关闭) − 反应型减仓 − 风控降档 , 0, 80% )
              基准：equity_base_mode="fixed"、equity_base_fixed=0.70（硬上限 0.80，永不满仓）
              调整带：±position_band_max（默认 0；制度+情绪驱动，不用账户收益）
              反应型减仓：**默认开启** ma_break_step=0.10（跌破 MA60/MA120 各减 10%，合计≤40%，底仓 40%）
              风控降档：组合级触发（自峰值回撤 ≥15% 或 相对本金亏 ≥15% 且评分<25）
                        → 权益降至 25%，冷却 5 个交易日后自动解除；
                        带**迟滞**：回撤收敛到阈值 −5pp 才重新武装（否则会永久锁死，见 §十四 第 1 条）
```

> 2026-09-11 更新：指数级择时层从"默认关闭"改为**默认开启**。上一轮"关闭"的结论来自
> 60/40 顺序切分 + 指数级近似 + 当时尚未修的组合止损锁死缺陷；改用**全历史 + 牛/熊/震荡
> 三窗口 + 基金级真实回测**后，结论反转为"同时提高收益、压低回撤"（§6.4/§6.5）。
> 若想回到"低回撤/高防御"档，把 `risk.ma_break_step` 调到 0.15–0.20、或关掉 `dynamic_weights`，
> 参数面板一键可切。

## 六、组合试错：选出最终引用的模型

> **口径已升级（2026-09-11）**：6.1 及以下两张表用的是"前 60% 选 / 后 40% 留出"的**顺序切分**，
> 用户指出它无法模拟牛熊——顺序切分只会切到一种市场状态。现口径为
> **全历史 + 牛/熊/震荡三组独立留出期**（§6.2 起），并且**以基金级真实回测为准**（§6.4/§6.5）。
> 下面这两张表保留为历史记录（它们的结论已被新口径部分推翻，特别是"指数级择时无用"）。

把已集成的各路模型/规则做成可开关的组合，在**同一数据**上比较（1930 天，含 20bp 摩擦、
最短持有 7 天），**前 60% 选组合、后 40% 只报告**：

| 组合 | 选择期(1158 天) 收益/回撤 | 留出期(772 天) 收益/回撤 |
|---|---|---|
| ① 满仓持有（参考） | +12.5% / 39.6%（0.32） | +16.4% / 21.4%（0.77） |
| ② 固定 60% | +9.8% / 25.5%（0.38） | +10.9% / 13.3%（0.82） |
| ③ 评分基础仓位 | +5.9% / 25.1%（0.24） | +8.1% / 13.0%（0.62） |
| ④ 评分+调整带 | +6.3% / 26.8%（0.24） | +4.8% / 13.4%（0.36） |

**结论（三条，都已落地）**：

1. **任何含"预测型模型层"的组合在两期里都亏钱**（−3%~−18% / −7.6%~−12.8%）
   → `risk_overlay_enable=false`，模型退化为**参考信号**（面板展示、LLM 判读）；
2. **"评分驱动仓位"不如固定适度仓位**（③ vs ②）→ `equity_base_mode="fixed"`；
3. **第一轮最优是 ⑪（固定 60% + 均线减仓 + 回撤冷却）**——留出期收益/回撤比 1.01（9.1% 回撤、
   +9.2% 收益），是"回撤最小"口径的赢家；选择期冠军 ⑩ 在留出期失效，
   正好证明"选组合必须留出期验证"。
   第一轮的权重是固定的（消息 20%/情绪 10%），第二轮（§6.1）把**权重与风控层一起**扫了 5760 组，
   在"收益优先、回撤不失控"口径下改成 **固定 70% + 不叠加指数级择时**（留出期 +13.0%/15.4%）；
   若改回"回撤最小"口径，对应档位是 ⑪ 那类组合（第二轮同口径为 score基准60%+均线+冷却，
   留出期 +7.8%/9.6%、回撤 9.6%）。两个口径都写在 §6.1 的表里，随时可切。

### 6.1 权重维度第二轮试错（5760 个组合，追求高收益 + 回撤不失控）

第一轮固定了权重，第二轮把**内部算法权重**也纳入扫描（消息 ∈ {20%,30%,35%,45%}、
情绪 ∈ {0%,10%,20%}、量化拿剩余）、基准仓位 ∈ {60%,70%,80%,90%,100%}、
基础模式 fixed/score、调整带开/关、风控层 4 种、硬上限 ∈ {80%,90%,100%}，
**全网格在两期都算**（选择期 1158 天 / 留出期 772 天，含 20bp 摩擦）。

**收益/回撤前沿（三个代表点）**：

| 档位 | 组合 | 选择期 | 留出期 |
|---|---|---|---|
| 最高收益 | 消息20%/情绪20% **score基准100%** 无风控 上限100%（≈满仓） | +10.8% / 38.4% | **+17.5% / 20.1%** |
| **★ 采纳（高收益+回撤可接受）** | 消息20%/情绪0–10% **fixed基准70%** 上限80% **不叠加指数级择时** | +10.8% / 29.3% | **+13.0% / 15.4%** |
| 两期最稳 | 消息20%/情绪0% score基准60% 均线+冷却（降仓25%）上限80% | +12.5% / 18.2% | +7.8% / 9.6% |

筛选口径：选择期回撤 ≤30%、留出期回撤 ≤20%、两期收益 >0（5760 组中 3672 组满足）；
"采纳"取其中留出期收益最高者，"两期最稳"取 min(两期 收益/回撤) 最大者。

**指数级风控层的定向代价**（基准 70%/消息 20%/情绪 10%）：

| 风控层 | 选择期 | 留出期 |
|---|---|---|
| **无（采纳）** | +10.8% / 29.3% | **+13.0% / 15.4%** |
| 仅回撤冷却（降仓25%） | +21.5% / 18.7% | **−3.9% / 12.8%**（追跌杀跌） |
| 仅回撤冷却（降仓50%） | +14.1% / 25.6% | +8.1% / 14.5% |
| 仅均线减仓 | +2.6% / 23.5% | +7.4% / 10.1% |
| 均线+冷却（降仓25%） | −3.2% / 18.0% | −7.8% / 12.9% |
| 均线+冷却（降仓50%） | +0.8% / 22.6% | +7.4% / 10.1%（冷却上限高于均线减仓后的 40% 下限，不再起作用） |

**结论**：
1. **指数级择时层（均线减仓 / 回撤冷却）在留出期让出的收益多于减少的回撤** → 默认关闭
   （`risk.ma_break_step=0`、`peak_trailing_pct=1.0`），需要"低回撤档"时改回 `0.2 / 0.10` 即可；
2. **基金级风控全部保留**（此处为指数级模拟，未建模基金级规则）：
   单只 −8% 止损、+10%/+25% 止盈、组合止损 −15%；
3. **消息权重降到 20%**（量化 70%）在留出期更好——与"消息面日级 IC 仅 +0.02"一致；
4. 采纳组合留出期 **+13.0% / 回撤 15.4%**，选择期 +10.8% / 29.3%，两期都为正；
   情绪分历史只有 266 天（快照回填所限），故 0% 与 10% 档在两期等价，线上仍保留 10%。
5. 定向对照中的所有风控层都用**显式设计值**（均线步长 0.2、合计上限 0.4、冷却阈值 10%、冷却 5 天），
   不继承线上开关，避免"线上关掉某层 → 对照表随之变化"的复现漂移。

> 复现：`python data/weight_combo_study.py`（5760 组合全网格，结果存 `data/weight_combo_study.json`）。

### 6.4 子系统阉割对比（基金级真实引擎，四窗口独立回测）

指数级 harness 只把消息/情绪分用于"评分驱动仓位"，测不出"消息面影响**选基**"。
所以子系统阉割对比改在**真实引擎**（`Engine.backtest`：point-in-time 重建备选池、真实申赎费、
基金级止损止盈、最短持有）上做，回放已接入十年消息库的当日消息分。

| 变体（只改一处） | 全历史 | 牛市 | 熊市 | 震荡市 |
|---|---|---|---|---|
| **线上配置**（固定70% + 基金级止损，指数级择时关） | +65.01% / 24.0% | +14.49% / 9.4% | −11.60% / 14.7% | +12.99% / 16.2% |

| 阉割情绪微观（`micro_enable=false`） | +65.01% / 24.0% | 同线上 | 同线上 | 同线上 |

**四条结论**：
1. **消息面是全系统最大的收益来源**：关掉它，全历史 **+65.0% → +25.5%**（少 40pp），
   且回撤反而更大（24.0% → 28.6%）。`news_weight` 取 0.20 还是 0.35 几乎无差别——
   **关键是"有没有消息面"，而不是给多少权重**；
2. **指数级择时层在基金级真有价值**（与上一轮指数级结论相反）：`均线减仓 + 回撤冷却`
   把全历史 **+65.0% → +80.1%**、回撤 **24.0% → 17.3%**、熊市 **−11.6% → −5.8%**；
   代价是牛市/震荡弹性变小（+14.5%→+7.5%、+13.0%→+4.9%）；
3. **基准 80% 与"关动态权重"都能提高收益但越界**（回撤 31.1% / 28.1% > 25% 上限），
   在 25% 上限内**不可采纳**；
4. **三处"改了没反应"是回放不覆盖，不是"没用"**：① 调整带 ±10% 小于 `regime_step`
   调仓阈值（12%），被阈值吸收；② 题材热度因子在历史区间没有热度快照（`heat_map` 为空）；
   ③ 预测型过滤器的信号文件只有"当天"的 p_up，回放没有历史信号序列。
   它们各自的十年结论来自专门脚本（`reactive_study.py`、`micro_study.py`、
   `risk_overlay_eval.json`），**不能**用本表一句"无影响"代替。

① 它与用户口述的"跌破均线减仓 20%"（步长 0.2）不同，0.10 是数据选出来的更温和档；
② 采用它是看"四窗口都不差"（牛市 +18.2%、震荡 +20.2%、熊市 −9.8%），

③ 敏感性扫描显示**这条参数曲线并不平滑**，所以单点最优**不可信**（见下表）。

| 敏感性（其余同 H） | 全历史 | 牛市 | 熊市 | 震荡市 |
|---|---|---|---|---|
| MA 步长 0.05 + 冷却 0.10 | +55.79% / 21.9% | +17.39% | −11.10% | +16.54% |

| MA 步长 0.20 + 冷却 0.10 | +80.09% / 17.3% | +7.46% | **−5.84%** | +4.87% |

> **+55.8% → +85.8% → +88.5% → +80.1% → +32.1%**：相邻档位能差 30–50pp，
> 冷却阈值 0.08 与 0.10 之间更是 +22.9% vs +85.8%。**这不是"精细调参的空间"，
> 而是"单路径回测的方差"**——每个参数值只对应一条历史路径，路径依赖（轮动时点、
> 止损触发次序）会把结论放大成噪声。因此：
> 1. 只应把 **0.10–0.20 视作一个"可接受平台"**（全历史 80–88%、回撤 17–20%、
>    四窗口均不越界），不要相信其中某一个是"最优"；
> 2. 平台之外（0.05 / 0.30）明确变差，可以排除；
> 3. 想更稳就选 **D（关动态权重，回撤 13.5%）** 或 **F（熊市 −3.4%）**，
>    它们用 10–15pp 的全历史收益换取更低的波动与更好的防御——
>    这三档都在参数面板里**一键可切**（`risk.ma_break_step` / `peak_trailing_pct` /
>    `dynamic_weights` / `news_weight`）。

> 复现：`python data/regime_backtest.py`（全部变体）或 `--only final_H,sens_ma015,…`（选跑），
> 结果存 `data/regime_backtest.json`。

## 十二、已知边界与诚实结论

1. **不承诺高命中率**：日频方向是接近有效市场，长期 52–56% 已是实测上限；
2. **不承诺任何收益**：默认目标倍数 ×1.3 意味着**半年 +30%**，折合日均约 +0.23%
   （70% 仓位下指数需 ≈+0.33%/日），属于高难目标——**本系统不承诺达成**；
   它提供的是纪律、口径与可复现的工具体系，实测「全历史 +85.8% / 回撤 19.9%」是**九年**的
   样本外回测结果，不是任何期限的承诺；
3. **参数曲线不平滑，单点最优不可信**：同一套逻辑只改均线减仓步长
   （0.05/0.10/0.15/0.20/0.30），全历史收益是 +55.8/+85.8/+88.5/+80.1/+32.1%——
   相邻档位差 30–50pp。这**不是可精细调参的空间，而是单路径回测的方差**；
   只能把 0.10–0.20 当"可接受平台"，并把平台外的档位排除（详见 §6.5）；
4. **回放口径有覆盖盲区**（会让人误以为"改了没用"）：调整带 ±10% 小于调仓阈值 12%
   被吸收；题材热度因子在历史区间没有热度快照；预测型过滤器没有历史信号序列。
   这三者的结论只能来自各自的专门脚本，**不能**用"回放里逐位相同"当作"无效"；
5. **指数级 ≠ 基金级，且两者会给出相反结论**：同一组"均线减仓 + 回撤冷却"，
   指数级近似说"让出收益更多"（§6.3），基金级真实引擎说"同时提高收益、压低回撤"（§6.4）。
   原因是基金级多了债基底仓、基金级止损与轮动路径，**结论以基金级为准**；
6. **样本外会失效**：上一轮"选择期冠军"（组合⑩）在留出期转负，是常态而非意外；
7. **数据依赖**：财联社 10 年电报、同花顺情绪、行情通道都可能变更或限流；
   K线缓存曾被兜底通道的短区间覆盖过一次（见 §十四 第 8 条），现在写回取并集、读取合并双键；
8. **本仓库全部结论可复现**（脚本在 `data/`，报告在 `data/*.json`），但**不构成投资建议**。

## 十六、起始资金与目标线可配置 + 全链路并行加速

### 16.1 起始资金与目标线（默认 1000 元 × 1.3，均可配置）

**唯一真值**：`account.target_multiple`（默认 1.3）。起始资金 `account.initial_cash` 可自定义（默认 1000），
目标金额 = 两者相乘，`account.target_value` 只是**镜像值**（写进配置便于人读，改本金/倍数时自动重算）。

| 入口 | 用法 |
|---|---|
| 命令行 | `python app.py init --cash 2500` → 目标线 3250；`--target-multiple 1.5` 或 `--target 4000` 可覆盖 |
| 网页参数面板 | 「运行与服务」组里的 **起始资金** / **目标倍数**，保存即生效（自动备份可回滚） |
| 生效范围（**其他算法完全没动**） | 界面目标进度与"还差多少"、回测的目标达成判定、LLM 提示词里的本金与目标、账户 meta |

规则细节（都有测试：`tests/test_account_plan.py`，13 项）：
* **本金来自账本**（记录的是实际投进去多少钱，配置改动不会篡改历史），**目标每次运行按
  「账本本金 × 配置倍数」重算** —— 所以把倍数从 1.5 改成 1.3 立刻生效，不用重新 init；
* 旧配置若只有 `target_value`、没有 `target_multiple`，则按 `target_value` 走（升级不漂移）；
* 倍数 ≤ 0 视为非法（`settings.validate` 拒绝），配置写坏会明确报错而不是静默 0。

### 16.2 并行加速（24 物理核 / 32 线程实测数字）

新增 `data/parallel.py` 作为并行底座，并明确了两条纪律：**只并行纯计算**（会写共享文件的
步骤留在主进程串行）、**只并行值得并行的部分**（过轻的任务并行反而更慢）。

| 任务 | 改造前（串行） | 改造后（并行） | 加速 |
|---|---|---|---|
| `data/regime_study.py`（6000 组组合 × 4 窗口） | 约 60–90 秒 | **3.9 秒** | ~20× |
| `data/regime_backtest.py`（31 变体 × 4 段 = 124 个引擎回测） | 实测累计 **6155 秒** | **243.6 秒** | **25×** |
| `data/audit.py`（23 个 CLI 子命令） | 约 2–3 分钟 | **34.9 秒** | ~4× |
| `data/audit_web.py`（34 个路由） | 约 90 秒 | **16.8 秒** | ~5× |
| `harness.build_base`（2172 天逐日指标） | 1.9 秒 | 0.9 秒 | 2.2× |
| 评分序列（15 组） | 0.08 秒 | **不并行**（并行实测 0.7 秒，更慢） | — |

实现要点：进程池（CPU 密集）× 线程池（HTTP/子进程）分工；worker 用 initializer 加载共享数据、
**自己读磁盘缓存**（不把几 MB 对象 pickle 给每个任务）；`FUNDAI_JOBS` 环境变量或 `--jobs N` 可限流；
研究跑批把计数器重定向到 `data/cache/study_usage.json`，避免并行 worker 争抢线上配额计数文件。

**命令行日常命令也接上了并行**（2026-09-12）：

| 命令 | 并行方式 | 说明 |
|---|---|---|
| `news-score-db [--jobs N]` | 进程池（纯计算） | 几十万条电报的正则+词典+事件语义打分；**读任务与写库留在主进程**（SQLite 单写者），worker 各自加载一次词典，结果与串行逐字段一致 |
| `news-fetch-db [--jobs N]` | 线程池（纯 I/O） | 把回溯区间均分成 N 段、每段一个线程各走时间游标翻页；写库靠 WAL 并发提交，`id` 主键 + INSERT OR IGNORE 幂等，重复抓取不重复计条 |

**受限环境自动降级**：进程池建不起来时（Windows 受限令牌/沙箱会让
`ProcessPoolExecutor` 在创建管道时抛 `PermissionError`），`parallel.probe_process_pool()`
会实测一次并让命令**退回串行**（只提示一次原因），绝不"默默算错"或整条命令失败。

**密钥与身份信息不在仓库里**：`config.json`（含数据源 Token 与 LLM api_key）不随仓库发布，

数据源默认走东财/新浪公开通道，**无需任何密钥即可运行**。

`python app.py demo` 生成一套可随意折腾的合成演示数据（只读库，不碰真实账户）。
