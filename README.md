## 1. 这个项目是什么

一句话：**它不预测神仙行情，它让你的每一次基金决策都有出处、可复盘、能自检。**

| 能力 | 说明 |
|---|---|
| **每日市场研判** | 量化技术面 + 多源消息面 + 涨停情绪微观 → 三路加权合成评分，附**逐条依据**与"评分怎么算出来的"完整拆解 |
| **AI 次日方向判断（自动记录 · 自检命中率）** | 评分推导方向（看多/看空/中性）→ 自动入库 → **下一交易日收盘自动结算命中率**，不需要人工输入，也不给自己"事后改口"的机会 |
| **基金筛选与仓位规划** | 动态备选池（动量/波动/追高惩罚）→ 选基、目标仓位、申赎费与最短持有期约束、轮动路径 |
| **反应型风控** | 单只止损/止盈、组合级止损（可再入 + 迟滞）、均线减仓、回撤冷却，全部有开关与回测依据 |
| **消息面管线** | 十年财联社电报库（SQLite，百万级）+ 事件语义推断（地缘/央行/业绩/减持/产品提示）+ 自学习词典 + LLM 逐条降噪 |
| **网页可视化** | 资产曲线、持仓盈亏、仓位结构、每日评分、研判正文、消息与进化、参数开关面板（126 个参数带中文说明）、数据源配额与降级状态 |
| **可复现实证** | 十年全历史 + 牛/熊/震荡三组独立留出期回测、6000 组组合扫描、子系统阉割对比，脚本与结论 JSON 都在仓库里 |

**默认配置**：起始资金 **1000 元**、目标倍数 **×1.3**、观察期半年 —— 只是开箱默认值，
用来演示"目标进度/达标判定"；本金、倍数、期限都可以改（详见 §5）。
系统的价值在**决策辅助与可复盘的纪律**，不在任何收益倍数。

## 3. 核心特性：AI 次日方向判断（自动记录 · 自检命中率）

网页「消息与进化」页右上角即为此面板。设计要点是**不给自己留后路**：

* 方向由**平滑后的合成评分**经统一口径推导（看多 ≥ +25 / 看空 ≤ −25 / 其余中性），
  判断日收盘**自动落库**；
* 下一交易日收盘后**自动结算**：看多=涨、看空=跌、中性=|涨跌| ≤ 0.3%；
* 跨天/跨周末照常显示（判断日自动归一到提供研判的交易日，同一份收盘数据不会重复计数）；
* 命令行可补跑与复核：

```bat
python app.py direction-check                      :: 今天：记录 + 结算
python app.py direction-check --date 2026-09-11    :: 补某个判断日
python app.py direction-check --refresh            :: 先用数据源刷新指数K线
python app.py direction-check --force              :: 同日重跑也覆盖方向
```

> **诚实边界**：日频方向预测在近有效市场的样本外上限通常 52–56%（本项目十年实测亦然）。
> 这条面板的意义**不是"证明系统很准"**，而是把准确性摆到台面上，让使用者清楚知道
> 该给系统的信号多少权重 —— 详见 [`README_TECH.md`](README_TECH.md) §11 / §12。

## 4. 性能：默认铺满 CPU（`--jobs` / `FUNDAI_JOBS`）

```bat
python app.py news-score-db --jobs 16     :: 消息库按线上口径打分（纯计算 → 进程池）
python app.py news-fetch-db --days 300 --jobs 8
                                          :: 财联社电报回填（纯 I/O → 线程池，分段并行）
set FUNDAI_JOBS=8                         :: 环境变量等价于 --jobs（1 = 串行）
python tools/bench_parallel.py --jobs 8   :: 并行基准：给你可复现的加速比
```

并行纪律（`data/parallel.py` 内有完整说明）：**只并行纯计算**（写库/写共享文件留在主进程
串行，避免锁表与计数漂移）、**只并行值得并行的部分**（过轻任务并行反而更慢）、
worker 各自读缓存而不是把大对象 pickle 给每个任务。
**受限环境自动降级**：进程池建不起来（受限令牌/沙箱会让 Windows 拒绝创建管道）时实测一次
并退回串行、只提示一次原因，绝不"默默算错"或让整条命令失败。

## 5. 配置你的资金与目标

```bat
python app.py init --cash 1000                          :: 默认：起始资金 1000，目标线自动 1300
python app.py init --cash 20000                         :: 目标线自动 26000
python app.py init --cash 5000 --target-multiple 1.5    :: 目标线 = 5000 × 1.5
python app.py init --cash 5000 --target 6000            :: 或直接指定目标金额
```

* **真值只有一个**：`account.target_multiple`（默认 1.3）；目标金额 = 起始资金 × 倍数，
  配置里的 `target_value` 只是便于人读的镜像值，改本金/倍数时自动重算；
* 起始资金以**账本**为准（记录真实投入），配置改动不会篡改历史；
* 网页参数面板「运行与服务」组里也能改起始资金 / 目标倍数，保存即生效、自动备份可回滚。

## 6. 复现全部实证结论

```bat
python -m unittest discover -s tests -p "test_*.py"   :: 全量测试（260 项）
python data/harness.py                 :: 划分牛市/熊市/震荡市三组留出期
python data/regime_study.py --dd 25    :: 25% 回撤上限下的 6000 组组合扫描（并行，数秒）
python data/regime_backtest.py         :: 基金级四窗口回测 + 子系统阉割对比（并行，数分钟）
python data/news_direction_study.py    :: 消息面方向性实测
python tools/audit_all.py              :: 全量审计：24 个 CLI 子命令 + Web 路由
```

核心结论（完整版见 [`README_TECH.md`](README_TECH.md) §6 / §11）：固定基准仓位（70%）+ 十年消息面 + 反应型风控
在 2017-09→2026-09（九个年度、四个独立市场状态窗口）做到 **+85.8% / 最大回撤 19.9%**
（同期沪深300 +18.6%）；**消息面是最大收益来源**（关掉它 +65.0%→+25.5%）；
而**参数曲线并不平滑、单点最优不可信**，所以默认配置取"可接受平台"而不是最优单点。

## 7. 仓库结构与数据说明

```
fundai/          主包：算法 / 引擎 / 数据源 / 消息管线 / 筛选与方向自检 / Web / 参数元数据
web/static/      前端（原生 JS + 本地 ECharts，离线可用）
data/            研究脚本与结论 JSON + 只读研究快照（见下）
tests/           260 项测试（含方向自检、并行、回放完整性、配置写入端等回归用例）
tools/           打包与验证（make_release / verify_release / audit_all / cache_to_db / clean_personal_data）
assets/          图标等静态资源
```

**仓库里有什么数据**：只读的**研究快照**——让读者开箱即跑、并让 §6 的结论可复现。
**仓库里没有什么**：任何个人持仓、成交记录、资产曲线、方向判断记录或参数改动历史；
`config.json`（含 Token 与 api_key）也不随仓库发布，首次运行自动生成干净的默认配置。

### 7.1 缓存已收进单个 SQLite（`data/cache.db`）

`data/cache/` 原本是**按日/按代码切分**的缓存（`micro_<date>.json` 约 260 个交易日、
`nav_<code>.json` 几十只基金、`kline_*.json` 数份指数长历史……），单个体积很小但**文件数上千**：
上传/同步的瓶颈在文件数，不在数据量。发布快照因此把它们收进**一个 `data/cache.db`**：

| | 目录式 JSON | `data/cache.db` |
|---|---|---|
| 文件数 | 337 个 | **1 个** |
| 占用 | 4.86 MB | **1.06 MB**（值做了 LZMA 压缩，321/337 条命中） |

运行时由 `fundai/cachestore.py` + `util.load_json()` 的**只读回退**按需读出，
读到的对象与原 `json.load` 完全一致，**算法口径一行未动**。读取优先级是
**磁盘 JSON 优先、库里快照兜底**：你自己跑出来的缓存永远比仓库里的快照新。

```bat
python tools/cache_to_db.py --keep-files   :: 只打包不删文件（先看体积对比）
python tools/cache_to_db.py                :: 打包并删除已入库的 JSON
python tools/cache_to_db.py --dry-run      :: 只统计
```

**仓库里没有的两个超大文件**（GitHub 单文件 100MB 硬限制，可自行重建）：

| 文件 | 体积 | 内容 | 重建命令 |
|---|---|---|---|
| `data/cls_history.db` | ~911 MB | 财联社电报库（百万级 / 十年） | `python app.py news-fetch-db --days 3650 --jobs 8` + `python app.py news-score-db --jobs 16` |
| `data/cache/cls_history.json` | ~192 MB | 同一批电报的 JSON 快照（中间缓存） | 上面第二条命令会重建 |
